# Story

## Бизнес-цель

Сделать процесс specification-driven development понятным и доступным каждому контрибьютору,
чтобы изменения с пользовательским или техническим влиянием имели согласованные границы и
проверяемые результаты.

## User story

Как контрибьютор, я хочу увидеть правила SDD и полный безопасный пример, чтобы подготовить и
провести спецификацию без догадок о стадиях, проверках и документации.

## Границы и non-goals

Работа меняет только документацию. Она не меняет CI, продуктовый код, порядок установки skills
или историю прошлых изменений.

## Критерии успеха

- README и CONTRIBUTING ссылаются на единый SDD-гайд.
- Гайд описывает пять стадий, согласования, роли трёх skills и требуемые доказательства.
- В `docs/specs` есть полный учебный пример, не выдающий непроведённый hardware-тест за факт.
