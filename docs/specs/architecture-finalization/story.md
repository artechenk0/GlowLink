# Story

## Бизнес-цель

Сделать GlowLink легко расширяемым и тестируемым без архитектурного overhead, сохранив текущий
Windows GUI, CLI и подтверждённые команды ленты.

## User story

Как разработчик GlowLink, я хочу один рабочий application API и явные внешние границы, чтобы
менять BLE, экран и хранение без дублирования сценариев в интерфейсах.

## Границы и non-goals

Не добавляются устройства, эффекты, несколько лент, другие ОС или новые protocol frames.
Внутренний Python API не сохраняется; пользовательские CLI и GUI контракты сохраняются.
Legacy settings/device JSON не мигрируются.

## Критерии успеха

- CLI, menu и GUI используют один application facade.
- Presentation не импортирует конкретные adapters; application не импортирует внешние слои.
- Конфигурация допускает missing/unknown/invalid поля без полного сброса.
- Быстрый color input и повторный sync не создают конкурирующие BLE workers.
- Автоматические проверки и ручной hardware checklist выполнены.
