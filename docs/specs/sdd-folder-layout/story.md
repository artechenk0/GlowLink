# Story

## Бизнес-цель

Сделать крупные SDD-спецификации удобными для чтения и сопровождения, не смешивая смысл задачи,
техническое решение и журнал выполнения в одном файле.

## User story

Как контрибьютор, я хочу видеть отдельные файлы story, technical и tasks, чтобы быстро находить
нужную часть спецификации и обновлять её без конфликтов.

## Границы и non-goals

Работа меняет структуру SDD-документации и instructions skills. Она не меняет CI, продуктовый
код или порядок согласования стадий.

## Критерии успеха

- Шаблон и обе существующие SDD-записи имеют `README.md`, `story.md`, `technical.md` и `tasks.md`.
- SDD-гайд, CONTRIBUTING и три skills используют путь к папке, а не к одному Markdown-файлу.
- Старый плоский учебный пример не остаётся альтернативным источником формата.
