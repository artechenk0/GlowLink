# Архитектура

GlowLink — небольшой модульный монолит с четырьмя смысловыми слоями. Такое разделение позволяет
менять интерфейс или системный адаптер, не перенося BLE-детали по всему проекту.

1. `presentation` принимает ввод CLI, terminal menu и pywebview и отображает готовые результаты.
2. `application` содержит единый `GlowLinkApplication`, DTO, конфигурацию и sync-сценарий.
3. `domain` реализует RGB, BLE-адреса, кадры поддерживаемого протокола и обработку изображения без ОС.
4. `adapters` реализуют три внешние возможности: BLE через Bleak, экран через MSS и JSON storage.

`bootstrap/composition_root.py` — единственное место, которое знает конкретные адаптеры.
Presentation получает собранный application facade и не импортирует Bleak, MSS, UUID или
`ConfigStore`. Application зависит только от трёх крупных Protocol-портов: `BlePort`,
`ScreenPort` и `ConfigRepository`. Направление зависимостей проверяет AST-тест.

Один facade намеренно заменяет классы-use-case для каждого короткого действия. Новая абстракция
добавляется только при наличии реальной внешней реализации или второй точки использования.
Управление соединением, сериализация BLE-операций и screen sync общие для всех интерфейсов.

Конфигурация хранится в одном `config.json` со `schema_version`. Неизвестные поля игнорируются,
ошибка одного поля не сбрасывает остальные. Старые `settings.json` и `selected-device.json` не
читаются и не мигрируются. Выбор устройства, монитор и настройки сохраняются сразу; последний
цвет — после штатного завершения.

Архитектурные решения описаны в [ADR](decisions/README.md), границы функций продукта — в
[product-scope.md](product-scope.md).
