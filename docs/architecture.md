# Архитектура

GlowLink разделён на логические слои:

1. **CLI, GUI и Web UI** принимают ввод, показывают состояние и не содержат BLE-логики.
2. **Сценарии приложения** координируют поиск, выбор, подключение, цвет и sync. Они принимают
   понятные приложению данные и возвращают результаты для интерфейса.
3. **Домен BLE и протокола** формирует кадры, хранит правила совместимости и управляет сессией.
4. **Системные адаптеры** связывают приложение с Bleak/WinRT, pywebview, mss и файловой
   системой.

Зависимости направлены только вниз: UI → сценарии → домен → адаптеры. Нижний слой не импортирует
верхний; `protocol.py` не зависит от Bleak, UI или Windows. UI не создаёт `BleakClient`, не
вызывает GATT-операции и не интерпретирует UUID: эти детали остаются на границе BLE и передаются
интерфейсу только как готовый результат.

Текущие сценарии могут быть размещены рядом с их входной точкой. Новый сценарий, общий для двух
интерфейсов, выделяется в модуль приложения, а не дублируется в CLI и GUI. Решения, меняющие эти
границы, фиксируются в [ADR](decisions/README.md).
