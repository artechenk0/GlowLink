# Стандарт текстов

Этот стандарт распространяется на все тексты проекта: документацию, README, skills, UI и CLI,
сообщения, комментарии и changelog. Текст должен быть точным, кратким и пригодным для своего
читателя. Источники фактов — код, тесты, справка CLI и записи подтверждённых hardware-тестов.
Не заявляйте поддержку устройства, команды или поведения без таких доказательств.

Пользовательские документы храните в `docs/`; README оставляйте для ориентации, установки и
частых сценариев. Используйте логичную иерархию заголовков, короткие абзацы и копируемые
PowerShell-примеры. UI и CLI формулируйте прямо: действие, результат и следующий шаг при
ошибке. Команды разработки выполняются из `app/` через `.venv\\Scripts\\python.exe`.

Обновляйте документацию вместе с изменением CLI, протокола, совместимости или UX:

| Изменение | Документ |
| --- | --- |
| Пользовательский сценарий или CLI | `README.md` и при необходимости `docs/README.md` |
| Граница продукта | `docs/product-scope.md` |
| Подтверждённый протокол или устройство | `docs/protocol-notes.md` и `docs/device-compatibility.md` |
| Существенное архитектурное решение | Новый ADR в `docs/decisions/` |

Запись ручного запуска на устройстве храните в `docs/hardware-tests/`, затем кратко отражайте
результат в матрице совместимости. Фейковые тесты не заменяют hardware-тест.

Статусы достоверности: **поддерживается** — повторяемо проверено на устройстве;
**экспериментально** — есть в коде или исследовании, но не подтверждено; **гипотеза** —
предварительное предположение.
