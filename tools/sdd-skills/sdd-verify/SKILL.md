# SDD verify

`$sdd-verify <путь к папке спеки>` проверяет реализацию и документацию по одной SDD-спецификации.

Сначала прочитайте `README.md`, `story.md`, `technical.md`, `tasks.md`, `AGENTS.md` и diff. Не
перезаписывайте несвязанные изменения. Продолжайте только при `stage: applied` в `README.md`;
иначе сообщите, какие задачи или проверки не завершены.

Сопоставьте реализацию с каждым критерием успеха из `story.md` и технической задачей из
`tasks.md`. В разделе `Результаты проверки` файла `tasks.md` добавьте таблицу: «критерий или
задача | доказательство | статус». Запустите проверки,
соразмерные изменению, согласно `AGENTS.md`. Для изменений GUI приложите или запросите
скриншот; для изменений BLE зафиксируйте требуемый ручной hardware-тест, не выдавая его за
выполненный.

Проверьте, нужна ли синхронизация документации. Меняйте только относящиеся к изменению файлы:
`README.md` для UX/CLI, `docs/product-scope.md` для границ продукта,
`docs/protocol-notes.md` и compatibility-матрицу для подтверждённого протокола/устройства, ADR —
для архитектурного решения. Если изменений нет, явно запишите, что документация актуальна.

При успехе добавьте в `tasks.md` результаты проверок и список синхронизированных документов,
затем переведите stage в `README.md` в `verified`. Если обязательная проверка, включая
hardware-тест, не выполнена, оставьте `stage: applied` и перечислите конкретные пробелы.
