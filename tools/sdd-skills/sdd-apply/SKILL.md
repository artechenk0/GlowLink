# SDD apply

`$sdd-apply <путь к папке спеки>` выполняет техническую часть одной SDD-спецификации.

Сначала прочитайте `README.md`, `story.md`, `technical.md`, `tasks.md`, `AGENTS.md` и текущий
diff. Не перезаписывайте несвязанные изменения. Продолжайте только когда в `README.md`
`stage: ready-to-apply` и `approvals.technical: approved`. Иначе остановитесь и сообщите, какое
согласование или переход не завершён.

Работайте последовательно по незакрытым задачам в `tasks.md`. Не расширяйте scope без обновления
`story.md` и нового согласования спеки. Следуйте `AGENTS.md`: UI не взаимодействует с BLE/GATT напрямую,
а аппаратные проверки не подменяются фейками.
Применяйте также `docs/standards/development.md` и `docs/standards/writing.md`.

Для каждой завершённой задачи:

- внесите ограниченные изменения реализации;
- добавьте или обновите автоматические тесты, если меняется поведение;
- отметьте задачу в `tasks.md` как выполненную;
- запишите выполненные команды и результаты проверки в раздел `Реализация` файла `tasks.md`.

Для задачи без автоматического теста укажите причину и предусмотренную ручную проверку. Не
отмечайте задачу выполненной, если её проверка не пройдена.

После выполнения всех задач и их запланированных проверок переведите stage в `README.md` в
`applied`. Не
объявляйте результат проверенным: для этого нужен `$sdd-verify`.
