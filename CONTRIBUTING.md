# Contributing

Используйте Python 3.12+ и запускайте из `app/`:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[test]"
python -m pytest
python -m pytest --cov=ledsetup --cov-report=term-missing
python -m ruff format --check src tests
python -m ruff check src tests
python -m mypy src
```

Подключите локальные проверки перед первым коммитом (из корня репозитория):

```powershell
python -m pre_commit install
```

Проверить все файлы вручную можно командой `python -m pre_commit run --all-files`.
Hook ускоряет обратную связь, но не заменяет CI: те же проверки запускаются в pull request.

## Specification-driven development

Для изменения пользовательского поведения, CLI, GUI, протокола, совместимости или архитектурных
границ ведите одну спецификацию в `docs/specs/<slug>/`. Полный порядок работы, стадии и
доказательства описаны в [SDD-гайде](docs/sdd.md).

До реализации зафиксируйте бизнес- и техническое согласования и переведите спеку в
`ready-to-apply`. В PR укажите путь к спецификации, её текущую стадию, выполненные проверки и
ограничения. До `verified` в спецификации должны быть отмечены задачи, результаты проверок и
список синхронизированной документации; для GUI приложите скриншот, а для BLE — результат
ручного hardware-теста или явно обозначенный пробел.

## Ветвление и релизы

Проект использует [упрощённый Gitflow](docs/gitflow.md). Не отправляйте изменения напрямую в
`main`: каждое изменение попадает в неё только через pull request.

Одна ветка и один PR соответствуют одной логической задаче. Рабочие ветки создавайте от
`main`, используя типовой префикс из правил Gitflow. Перед открытием PR обновите ветку от
`main`, выполните обязательные проверки и убедитесь, что diff относится только к задаче.

PR описывает пользовательское поведение, связанные issue, выполненные проверки и ограничения.
Для GUI приложите скриншот; для BLE укажите модель устройства, команды и результат ручной
проверки. Обновляйте README, compatibility-матрицу, protocol notes и ADR, когда меняется их
предмет. Дополнительные правила находятся в [AGENTS.md](AGENTS.md).
