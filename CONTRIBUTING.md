# Участие в разработке GlowLink

[English](CONTRIBUTING.en.md) | **Русский**

Спасибо за вклад. Один pull request должен решать одну понятную задачу и не смешивать новую
возможность с несвязанным рефакторингом.

## Быстрый старт

Нужен Python 3.12+. Все команды ниже выполняются из папки `app/`.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[test]"
python -m pytest
python -m ruff format --check src tests
python -m ruff check src tests
python -m mypy src
```

Для отчёта о покрытии добавьте:

```powershell
python -m pytest --cov=ledsetup --cov-report=term-missing
```

Установите локальные проверки один раз из корня репозитория:

```powershell
python -m pre_commit install
```

Полный ручной запуск: `python -m pre_commit run --all-files`. Эти проверки ускоряют обратную
связь, но CI в pull request всё равно обязателен.

## Рабочий процесс

1. Создайте короткоживущую ветку от актуальной `main`. В Codex используйте префикс
   `codex/`; остальные соглашения о ветках описаны в [Gitflow](docs/standards/gitflow.md).
2. Внесите изменение и добавьте тесты. Для BLE и экрана используйте фейки из `app/tests/`,
   чтобы тесты не требовали оборудования.
3. Выполните подходящие проверки из раздела выше.
4. Откройте pull request в `main`. Опишите поведение, связанную issue (если есть), проверки и
   известные ограничения.

Для изменения GUI приложите скриншот. Для BLE укажите модель устройства, команды и результат
ручной проверки. Не заявляйте поддержку нового устройства только на основании похожего имени,
UUID или успешного теста с фейком.

## Когда нужна спецификация

Заведите одну запись в `docs/specs/<slug>/`, если меняются пользовательское поведение, CLI, GUI,
протокол, совместимость или архитектурные границы. Полный процесс — в
[SDD-гайде](docs/standards/sdd.md). Для простых правок текста и механических изменений без изменения
поведения спецификация не нужна.

## Документация и решения

Обновляйте документацию вместе с изменением:

| Изменение | Где отразить |
| --- | --- |
| Пользовательский сценарий или CLI | `README.md` и при необходимости `docs/README.md` |
| Граница продукта | `docs/product-scope.md` |
| Подтверждённый протокол или устройство | `docs/protocol-notes.md` и `docs/device-compatibility.md` |
| Существенное архитектурное решение | Новый ADR в `docs/decisions/` |

Новый результат на реальном устройстве фиксируйте в `docs/hardware-tests/`, а затем кратко
суммируйте в матрице совместимости. Полный набор общих правил — в
[стандартах проекта](docs/standards/README.md); обязательный минимум для агентов — в
[AGENTS.md](AGENTS.md).
